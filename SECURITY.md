# Security policy

This repository is my static user site, published with GitHub Pages. It has no server, no forms and no user data, but I still want to hear about anything that could harm someone visiting it.

## Reporting a vulnerability

Please report it privately, not in a public issue (issues are off here anyway):

1. Open the repository's **Security** tab and choose **Report a vulnerability** (GitHub private vulnerability reporting).
2. Describe what you found, the page it affects, and the steps to reproduce it.

I aim to reply within a week, fix confirmed problems on `main` (the published site is always the latest commit), and credit you unless you'd rather stay anonymous.

## Scope

In scope: the pages and assets in this repository and the workflows that build and publish them, for example a link that leads somewhere harmful, a script or asset loaded from somewhere it shouldn't be, or a workflow that could be abused.

Out of scope: GitHub Pages itself, and the projects this site links to. Report a problem in [docling-batch-extract](https://github.com/saibal-roy/docling-batch-extract/security) through its own Security tab.
